# Android BeautySDK 规则

## 管线与引擎边界

- 输入来自宿主直播引擎，输出返回编码前处理链路。先核实选定版本支持修改/替换帧的接口，观察回调不等于处理接口。
- 记录引擎版本、输入输出格式、回调线程、同步/异步交回方式、帧生命周期及预览/远端是否使用同一处理结果。Zego 与声网分别适配，不猜测签名。
- 渲染优先评估纹理输入输出；只有 CPU 帧时按实际格式实现转换。测量读回、上传和颜色转换成本，不能把纹理 ID 当跨上下文可用资源。

## 帧与坐标契约

- 帧描述包含宽高、格式、时间戳及其单位、旋转、镜像、裁剪和纹理变换；CPU 平面包含 stride/pixel stride，纹理区分 OES/2D。
- 明确输入、分析图、检测结果和输出画面的坐标空间与变换顺序，覆盖前后摄、横竖屏、裁剪和宽高比变化。
- 分析缩小图像不改变输出视频分辨率。关键点附带采样时间与变换信息；切摄像头、重启或尺寸变化时丢弃旧结果。
- 明确 retain/release 或复制规则，不在引擎回调返回后继续使用失效的缓冲/纹理；异步分析使用有效期足够的数据。

## 检测调度

- 单人脸原型使用 MediaPipe Face Landmarker；实际版本、模型来源、校验和与许可在引入时记录，默认关闭非必要表情输出。
- 分析支路异步且有界，忙时丢弃或替换待分析帧，不积压。输入时间戳满足所选 API 的单调性要求。
- 渲染使用最近有效结果；配置最大结果年龄，人脸丢失或超时隐藏挂件，不能无限沿用最后一次坐标。
- 平滑/预测需与快速转头延迟共同评估，不用“必达 30 FPS”或未经测量的推理耗时作承诺。
- CPU/GPU delegate 均需结合转换和渲染成本评估；按所选版本约定创建、调用与释放检测器，避免并发关闭与晚到回调。

## OpenGL 与资源

- 明确 EGL context 所有权、共享关系、当前线程和同步方式；GL 创建、使用和释放在合适上下文中完成。
- 定义 FBO/输出纹理生命周期和复用时机；恢复宿主需要的 GL 状态，避免污染引擎渲染。
- 美颜、挂件变换与 alpha 合成分别验证；明确颜色空间、通道顺序、预乘 alpha，避免倒置、色偏、黑边。
- 初始化/停止/重启/释放保持状态一致，处理 context 丢失、后台切换和晚到检测结果。失败时按契约旁路原帧并报告可诊断错误，避免黑屏和线程阻塞。

## 验证与性能

- 三组对比：不开特效 / 开检测 / 开检测并合成；美颜叠加另列配置。固定设备、分辨率、目标帧率、ABI、delegate 和效果参数。
- 分别记录转换、推理、渲染与端到端时延，至少区分平均值和尾延迟；记录输入/输出/分析 FPS、丢帧、CPU/GPU、内存、温升及持续时长。
- 覆盖无人脸、遮挡、快速转头、进出画面、旋转镜像、切摄像头、启停重入、超时与资源释放。
- 检查远端解码后的画面，不以本地预览正确作为推流合成成功的证明。
- 分别测量模型、AAR、各 ABI 宿主 APK/AAB 增量及运行内存；构建、静态检查、单元测试和设备性能分别记录。
