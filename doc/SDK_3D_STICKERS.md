# 实验性刚性 3D 贴纸

支持单人脸、不透明顶点色三角网格、头部三维旋转跟随和粗略深度遮挡。当前内置眼镜、礼帽、皇冠、猫耳、耳机和包头棒球帽。使用已有 MediaPipe 模型和 ES3，不增加检测模型、第三方渲染引擎或新 SO，不接管相机。当前不是完整 glTF/GLB/PBR、纹理材质、骨骼动画、表情驱动或多人脸方案。

## Demo

Demo 的三维模式优先在 MediaPipe GPU 后端运行（初始化失败回退 CPU），以降低检测延迟导致的结果过期；二维沿用原选择。这是 Demo 执行策略，不改变公共 SDK 默认，也不延长 150ms 有效期。设备短测与真人验收状态见测试报告。

进入相机 → 贴纸 →「3D 贴纸（实验）」横向滑动选择眼镜、礼帽、香槟金皇冠、珍珠猫耳或薄荷色耳机。每个三维选项均有立方体标识和 3D 名称；普通 PNG 贴纸不标为三维。选择「普通贴纸」恢复原有资源效果。选择保存在宿主私有偏好，退出重开恢复；清除贴纸、重置贴纸分类和重置全部会关闭 3D。

新增三款为项目自有程序网格，通过 `BuiltInStickers3D.crown()`、`pearlCatEars()`、`headphones()` 获取；没有外部模型下载或第三方素材许可依赖。当前仍是内置试戴入口，不属于资源中心可导入的 PNG 包或 CMS 三维资源协议。

开启期间明确暂停二维贴纸、二维美型（瘦脸/大眼/瘦鼻/下巴/嘴部）及实验二维块匹配跟踪，保留原参数。磨皮、美白、调色、贴妆与背景/运镜仍可组合。公共渲染器直接收到 3D＋美型时抛出可诊断参数错误，不静默改参数。Demo 在构建有效快照时显式移除美型，界面显示提示，关闭 3D 后恢复保存的参数。

## SDK 接入

仍使用单一 Maven 入口，新增类属于 `lib_beauty`，默认关闭不创建 3D GL 资源。

```kotlin
// 在当前 ES3 EGL context/线程创建、render 和 close。
val renderer = BeautySceneRenderer(
    GlSticker3DRenderer(GpuPixelBeautyRenderer(context)),
    masks = null, // 需要背景时显式提供蒙版组件
)
val pipeline = BeautyEnginePipeline(
    factory = MediaPipeFaceAnalyzer.factory(context, output3D = true),
    renderer = renderer,
    textureAnalysis = true,
    onError = { error -> report(error) },
)
pipeline.settings = BeautySettings(
    smoothing = .3f,
    sticker3D = BuiltInStickers3D.glasses(),
)
```

完整编排顺序：背景合成 → 基础美颜/贴妆 → 3D 深度合成 → 数字运镜 → 可选手势动画。3D 包装器拥有并关闭 delegate；不要重复关闭。接受 OES/2D，先采样输入 transform，输出 identity 2D；rotation/mirrored 元数据保持原值。输出为借用纹理，下次 render/close 失效；异步消费仍需复制租约或由宿主同步。无跨 EGL context 共享或主链路 GPU 读回。

开启模型 `output3D` 是显式选择，旧 MediaPipe 调用保持关闭。若使用 `BeautyAnalysisRuntime` 的二维 motionEstimator，3D 期间必须关闭该跟踪；它不能估计新的 yaw/pitch。Demo 已处理。无有效三维观测、无脸、退化姿态、未来或过期结果时不绘制 3D；最大姿态年龄不能超过 SDK 默认 150ms。它不是持续帧率或真人稳定性的保证。

## 坐标与资源

### 包头棒球帽（2026-10-30）

`BuiltInStickers3D.baseballCap()` 返回项目自有的完整棒球帽网格：开放双层帽冠、封边帽口、有厚度的弯曲帽檐、前徽章、侧标及后扣。相机「3D 贴纸」新增棒球帽，二维模式返回三维时默认展示它，已保存的款式仍恢复。

`StickerMesh3D(positions, colors, indices, headOcclusion = true)` 是新增重载，旧三参数构造器及 Sticker3D 的构造/copy 不变。该模式同时启用帽类标准坐标贴合和估算头部深度；只适用于按该头部坐标制作的网格，不宜直接用于眼镜等旧素材。帽口基准 y=0.58，顶部约 y=1.50，头部中心约 (0,0.30,-0.35)，单位仍为眼距。运行时根据两侧脸部关键点在头部局部轴上的宽度做有界横向/深度缩放，额头位置修正高度；不是物理头围测量。

渲染依旧使用真实三维观测和 150ms 有效期：先写现有脸部深度，再按未受饰品 scale/offset 影响的头部矩阵写入椭球深度，最后绘制帽子。头部网格只写深度，不覆盖原视频颜色/alpha；静态头网格使用独立 VAO/VBO/EBO，首用上传，后续不因帽子切换重复上传。faceOcclusion=false 同时关闭两种遮挡，旧三参数网格不新增头部深度。

头部椭球只用于减少后帽沿穿到头前的现象，不能重建头发、耳朵、手和真实后脑勺，也不解决快速运动延迟。合成背面视角只验证模型确实有背面；完全背对镜头时，人脸关键点可能丢失，效果应按原过期策略隐藏，不能描述为已支持360°真人跟踪。真人贴合、持续性能与验证范围以测试报告为准。

- `FaceGeometry3D` 保存真实检测时间和固定顺序的 468/478 点；当前渲染器按 MediaPipe 人脸拓扑使用眼外角 33/263、额头 10、下巴 152 等索引。不得将其他拓扑的数据直接传入。
- `FacePoint3D.x/y` 位于原始帧归一化空间，`z` 向画面后方为正、以原始帧宽度为单位，是模型相对深度，不是毫米或测量距离。旋转、镜像、等比例裁剪/留边映射同时维护此单位；非等比像素拉伸保留二维观测并移除三维观测。
- 基于三维眼距和额头/下巴方向建立刚性局部基底，采用弱透视投影。附带的 canonicalTransform 原样保留于转正分析空间，映射不修改源矩阵；不能直接当作原始画面 MVP。
- `StickerMesh3D(positions, colors, indices)` 复制输入；xyz 每顶点3项、rgba 每顶点4项、索引每3项一个三角形。不透明顶点色，单网格不超过32768顶点/32768三角形，坐标限于 ±4 个眼距。模型 x 向右、y 向头顶、z 向观众；原点为眼外角中点，一个单位为三维眼外角距离。
- `Sticker3D` 可设置等比缩放、三轴偏移及 faceOcclusion。网格仅切换时上传 VBO/EBO，模型必须在 IO/资源准备线程创建，不在视频回调解析。
- 遮挡使用鼻部到脸部轮廓的深度扇形近似，并非完整精细人脸网格；不支持头发、手、后脑勺和精细鼻梁遮挡。支持深度自遮挡，保留输入视频 alpha。
- 当前自定义模型通过 SDK 内存 API 提供；旧 PNG ZIP、统一资源库协议与 CMS 未新增三维类型，不能把 GLB 或自定义网格伪装成 PNG 包上传。CMS 三维编辑/导入、格式版本与服务器校验是后续独立工作。

Release 沿用既有 FACE＋STICKER 授权门禁，没有新增权限名称或绕过授权。旧构造器、旧 copy/factory 的 JVM 描述符通过兼容重载保留；具体检查结果见测试报告，不等于 Kotlin 元数据/native/所有行为兼容已验收。

## 2026-10-30 饰品质感更新

内置眼镜使用镂空双层框、金色包边、铰链与弯曲镜腿；礼帽使用连续旋转曲面的卷边帽檐/收腰帽冠、缎带和扣饰。仍为SDK自有顶点色几何体，不含第三方下载模型。渲染器在网格切换上传时生成面积加权平滑法线，逐帧只由GL执行方向主辅光、固定高光和弱轮廓光；不增加模型推理，也不在帧回调重新计算网格法线。

这是表现3D体积的风格化着色，不是PBR、环境反射、真实投影或透明镜片；弱透视姿态和脸部扇形遮挡的限制不变，也不是三维美型或精细人脸重建。新增512px正面/左右侧转合成夹具验证覆盖、明暗变化与alpha；具体执行结果见最新测试报告，合成夹具不代替真人佩戴观感。

## 验证范围

JVM 覆盖不可变资源、非法输入、旋转镜像、等比映射与非等比拒绝、姿态年龄、yaw 三维投影。设备夹具覆盖深度遮挡、切换、GL 宿主状态恢复、原生美颜＋最终运镜、现有模型输出；UI 覆盖选择/关闭/重开恢复。最终执行证据与未完成项目见 [TEST_REPORT](testing/TEST_REPORT.md)。合成夹具和公开静态人像不等于真人快速转头观感、长时性能、多设备、直播引擎或 iOS 验收。
